# Critique — ops and verification lens (S67 plan)

Read: plan.md, waves.md, contracts.md, critique-product.md, the five reader reports, and the code the findings cite (globals.css, next.config.ts, sw.js, the three profile selects and their fallbacks, missing-column.ts, the migration recipe in 20260916130000_post_edited_at.sql, check-pwa.mjs, leave-device-clean.ts, package.json). 2026-09-26. READ-ONLY; nothing in the app touched.

## Verdict

The plan states the right ops rules (migration before deploy with a missing-column guard, tokens from day one, 150-line edits, commit and push per wave, a browser pass at two widths as a non-admin) but two of them do not work as specified and the rest are not yet a procedure. Two blockers. First, the wave 1 strip is styled with tokens (`--glass`, `--tag-ink`, `--scrim-rgb`, `--ink-2`, `--paper`, `--glass-border`) that globals.css only gains in wave 3, and no wave 1 batch owns globals.css, so the strip would ship to prod with undefined colours. Second, contracts C3 puts `profile_layout` into the three BASE selects, which are the FALLBACK selects the routes retry with, and the guard is called with the default M1 column list, so a missing `profile_layout` neither matches the guard nor survives the retry: the safety net the plan leans on is dead as written. Beyond those: the verify command `npm run typecheck && npm test` does not exist in package.json (the house commands are `npx tsc --noEmit` and `node --test`); "flip the default to Auto is one line" is really five files plus a service-worker bump; every push is a production deploy (no vercel.json, no workflows: Vercel's Git integration on main) yet no verify line says whether the browser pass runs before the push on a production build or after on the live URL, none names the non-admin account, wave 4 never checks the desktop shell, and no wave has a rollback line. Each fix is a paragraph in waves.md or contracts.md; the per-wave checklist at the end is offered as that paragraph.

## Verification checklist per wave (proposed replacement for the "Verify:" lines)

Common to every wave, in this order. ACCOUNT = the named non-admin test student, signed in once in its own browser profile (never a magic link in the admin's browser). Widths: 375 (phone, `MobileShell`) and 1280 (desktop). Every batch and review agent writes its notes to disk within its first 8 tool calls.

1. `npx tsc --noEmit` and `node --test …` (the command in the test file headers) clean.
2. `rm -rf .next && npm run build && npm start`; walk the wave's screens below on `http://localhost:3000` as ACCOUNT.
3. Commit, push (no asking). Wait until `gh api 'repos/{owner}/{repo}/deployments?per_page=1' --jq '.[0].sha'` equals the wave sha and the deployment is Ready.
4. Live: re-walk the two starred (*) screens on `https://www.connectvibe.app` as ACCOUNT; curl the served stylesheet for the wave's tripwire rule (below). If it is missing, the build served stale assets: redeploy, do not trust git.
5. Rollback line in the commit message: `git revert <sha> && git push`, or Vercel Instant Rollback.
