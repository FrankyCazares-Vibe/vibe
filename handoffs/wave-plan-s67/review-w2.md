## Findings (file · line · severity)

1. `public/html/profile.html` · ~7697 (`_readProfileLayoutFromDom`) · **SHOULD** — `setupReorderable('.profile-right','[data-widget]')` lets the owner drag a docked bio below Resume or Working on, but the document can't say that (C3: RIGHT = bio first), so `_readProfileLayoutFromDom` writes `bioSide:true` and `applyProfileLayout` puts the bio back on top at the next apply. The owner sees the new spot stick (the post-sync echo never re-renders sections), then it snaps back on reload. Fix: end `_onProfileLayoutChanged` with `applyProfileLayout(_readProfileLayoutFromDom())` so the DOM always shows what persists (idempotent, only out-of-place cards move), or make the docked bio's grip inert: `.profile-right > [data-widget="bio"] .drag-handle { display:none }`.
2. `src/components/mobile/ProfileMobile.tsx` · 1440 and 2152/2161 · **SHOULD** — the header tag row still merges `skills` (cap 6) into the interest tags for everyone, so hiding the Skills widget hides the Portfolio sub-section but the skills stay at the top of the visited profile; the desktop hides them completely. Breaks "a hidden widget must be indistinguishable from a never-filled one" (reader §Deliverable 4) and makes the two surfaces disagree on what `hidden:["skills"]` means. Fix: compute `layout` first, then `const skills = layout.hidden.includes("skills") ? [] : (user.skills ?? []).filter(Boolean).slice(0, 6);`.
3. `src/lib/profile/profile-layout.ts` · 44 (`WIDGET_IDS`) · NICE — contract-correct, not drift, but product-visible: the default phone Portfolio order changes for every existing profile from Working on · Experience · Resume to Experience · Skills · Resume · Working on, because the phone now derives from the desktop's default order. Nobody named this in plan.md §A. Fix: confirm on the 375 walk and write it into the journal/handoff; if Franky wants Working on first on phones, a phone-only projection in `portfolioWidgetOrder` (move `working_on` to the front when the layout `isDefaultLayout`) is three lines and keeps one document.
4. `public/html/profile.html` · ~5930 (`sectionEls` / IntersectionObserver) · NICE — `sectionEls` is captured once; in edit mode a hidden ghost card is `display:block` and still intersects, so the observer can activate a `hidden` pill (no visible active pill while scrolling past a ghost). Edit mode only. Fix: in the callback skip entries whose `target.classList.contains('widget-hidden')`.
5. `public/html/profile.html` · ~7735 (`_refreshWidgetControls`) · NICE — the desktop eye flips both `aria-pressed` and its label ("Hide X" ↔ "Show X"), so a screen reader hears "Show Skills, pressed"; the phone keeps one label with the opposite pressed convention (pressed = shown). Pick one: keep the desktop label constant ("Hide <label>") and let `aria-pressed` carry the state, and align the phone to the same reading.
6. `public/html/profile.html` · ~7715 and `ProfileMobile.tsx` · ~426 · NICE — copy "hidden · only you can see this" / "hidden · only you see it" is not quite true: the owner also can't see it outside edit mode (desktop) or outside the sheet (phone). Suggest "hidden · shows only while you edit".
7. `src/app/api/me/profile-sync/route.ts` · 430 and `src/app/api/me/profile/route.ts` · 174 · NICE — "never accept a partial" is implemented as fill-to-default, not 400: a hand-crafted `{profile_layout:{hidden:["bio"]}}` resets `order` to the default. Both real clients send whole documents, so no live path hits it; noting for the security sentinel. No change needed.
