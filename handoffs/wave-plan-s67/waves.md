## The procedure every wave follows

ACCOUNT = **blake**, the non-admin test student (never `fgcazares04@gmail.com`, an admin), signed in once in its own browser profile; magic links don't switch accounts inside one browser. Widths: 375 (phone shell) and 1280 (desktop shell).

1. Implement: 3–5 file-owned batches in parallel. One owner per file. Every Write/Edit ≤150 lines. Each batch writes `handoffs/wave-plan-s67/notes-wN-<batch>.md` within its first 8 tool calls and appends as it goes (a stall or a sleep must not lose the work).
2. Review: one adversarial reviewer per wave, read-only, writes `handoffs/wave-plan-s67/review-wN.md` early and appends; findings go back to the owning batch for repair.
3. Gate: `npx tsc --noEmit` and `node --test $(git ls-files 'src/**/*.test.ts')` clean (W1a adds `typecheck` and `test` scripts to package.json so the gate is one command from then on).
4. Local production build: `rm -rf .next && npm run build && npm start`; walk the wave's screens on `http://localhost:3000` as ACCOUNT (the dev server's Turbopack cache is still on; never trust `next dev` for this).
5. Commit and push without asking (push = production deploy). Wait until `gh api 'repos/{owner}/{repo}/deployments?per_page=1' --jq '.[0].sha'` equals the wave sha and the deployment is Ready.
6. Live: re-walk the starred (*) screens on `https://www.connectvibe.app` as ACCOUNT; `curl` the served stylesheet for the wave's tripwire rule. Missing = stale assets: redeploy, don't trust git.
7. Rollback line in the commit message: `git revert <sha> && git push`, or Vercel Instant Rollback to the previous Ready deployment. Wave 2's column is additive with a default and stays in place.
