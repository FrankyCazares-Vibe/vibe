# Critique — engineering feasibility lens (S67 plan)

Read: plan.md, waves.md, contracts.md, critique-product.md (its accepted findings are already in the plan and are not repeated), the five reader reports, and the code the plan cites. 2026-09-26. Read-only; no app code touched.

## Verdict

The plan is buildable and its code claims are honest: `resolveCampusRequest` (campus-request.ts:96) and `campusScopeError` (community-scope.ts:442) exist with the shapes the plan assumes; vaul and `PortfolioEditorShell` are already in ProfileMobile.tsx (lines 6, 3907); `vibe-no-scrollbar` is globals.css:2707; `isMissingColumnError` is src/lib/db/missing-column.ts:25; `setupReorderable(listSelector, itemSelector, onChange)` is profile.html:7414; the Otto settings PATCH is a `switch` allowlist that drops unknown keys and answers `noop` (route.ts:77-107, 131), so `case "theme"` is a five-line add; `@custom-variant dark (&:is(.dark *))` is globals.css:5; `CAMPUS_CHANGE_COOLDOWN_MS = 30 days` is onboarding-prefill.ts:395 and every test uses the constant, not the literal; `formatUpcomingChip` (9340) and `OttoFeedStrip` (13288, mounted 5672 and CampusMobile.tsx:671) are where the plan says; both profile bootstraps read with the service role, so "no authenticated grant" on `profile_layout` is safe; the 21-column tripwire (self-write-columns.test.ts:34) is owned by the batch that trips it. No wave has two batches on one file. **Two things would ship broken as written.** First, the wave-1 contract paints the strip with tokens (`--glass`, `--glass-border`, `--tag-ink`, `--ink-2`, `--scrim-rgb`) that only get defined in wave 3, and no wave-1 batch owns globals.css, so every chip would render with no background, border or colour. Second, three of the token names the contracts lean on (`--muted`, `--accent`, `--border`) are shadcn names: the unlayered shadcn `:root` block shadows the Vibe values in `@layer base`, so `var(--muted)` is near-white today (`oklch(0.97 0 0)`), not `#8A8580`, and the C4 replacement map `#8A8580 → var(--muted)` would wash out muted text on every surface it touches. Both are cheap to fix in contracts.md before wave 1 starts. Below those: a handful of contract gaps two owners would fill differently (the `roll` prop, how the phone learns the strip is hidden, the `EventCard` root that cannot take an `id`, a `campusQuery` helper that breaks two bare URLs, a missing-column guard that re-selects the column it is guarding), one hydration trap in the theme boot script, and one batch (W3a) that is three agents' work.

Blockers: 2. Should-fix before the wave that owns them: 9. Nice: 3.

## Checked and holds (no finding)

- `resolveCampusRequest(raw, viewer)` wraps `resolveScopeV2` and adds the no-system clamp (campus-request.ts:96-107); `campusScopeError(scope)` returns `{status, body}` (community-scope.ts:442-456). The trending route already calls `resolveCampusRequest(null, …)` (route.ts:4, 78), so W1a's `?campus=` is a one-argument change. The feed route imports `resolveScopeV2` directly (feed/route.ts:6), so W4a's switch to `resolveCampusRequest` is the right fix for R10.
- Otto settings PATCH: `sanitizePatch` is a `switch` that drops unknown keys (route.ts:77-107) and answers `{noop: true}` when nothing survives (:130-131); the plan's "`noop` = failure" rule is correct.
- Both profile bootstraps and the sync echo read through `createSupabaseServiceClient()` (profile-bootstrap:61, users/[handle]/bootstrap:89, profile-sync:828), so a `profile_layout` column with no `authenticated` grant cannot produce a permission error. `ProfileView` is consumed only by files W2a owns plus `build-vibe-user-v1.test.ts` (also W2a's).
- The 21-column tripwire (`self-write-columns.test.ts:34`) and `SELF_PROFILE_WRITE_COLUMNS` (21 entries, self-write-columns.ts:25-47) are both in W2a's Owns; `unexpectedSelfWriteKeys` gates both write routes (profile/route.ts:350, profile-sync:690).

- `<html suppressHydrationWarning>` is the right scope for the `data-theme` attribute; `@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *))` is valid Tailwind v4. The standalone cream overrides (globals.css:2887-2901, unlayered `#FAF7F2`) are in W3a's list.
