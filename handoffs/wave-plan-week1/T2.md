**A. Notifications: students can no longer insert rows**

A1. Live hole (verified 2026-09-21). `public.notifications` has policy `notifications_insert_as_actor`
`FOR INSERT TO authenticated WITH CHECK ((auth.uid() = actor_id) AND (type = 'mention'))` (from
`supabase/migrations/20260515100000_notifications_mention_type.sql:38-44`). Grants are
`anon=arwdDxtm, authenticated=arwdDxtm`. So any signed-in student can send
`POST /rest/v1/notifications {"user_id":"<anyone>","actor_id":"<self>","type":"mention","post_id":"<any post>"}`
(or `message_id` for any message) as often as they like. That creates a fake @mention in anyone's feed
and badge count, with no rate limit and no check that the post or message mentions them.
The policy only checks `actor_id`. Nothing validates `user_id`, `post_id`, `message_id` or `org_id`.

-- §B one like / follow notification per pair while an earlier one exists.
create or replace function public.notify_on_like_insert()
returns trigger language plpgsql security definer set search_path = public
as $$
declare
  post_owner uuid;
begin
  select user_id into post_owner from public.posts where id = new.post_id;
  if post_owner is null or post_owner = new.user_id then
    return new;
  end if;
  if exists (
    select 1 from public.notifications n
     where n.user_id = post_owner and n.actor_id = new.user_id
       and n.type = 'like' and n.post_id = new.post_id
  ) then
    return new;
  end if;
  insert into public.notifications (user_id, actor_id, type, post_id)
  values (post_owner, new.user_id, 'like', new.post_id);
  return new;
end;
$$;

create or replace function public.notify_on_connection_insert()
returns trigger language plpgsql security definer set search_path = public
as $$
begin
  if new.follower_id = new.following_id then
    return new;
  end if;
  if exists (
    select 1 from public.notifications n
     where n.user_id = new.following_id and n.actor_id = new.follower_id
       and n.type = 'follow'
  ) then
    return new;
  end if;
  insert into public.notifications (user_id, actor_id, type)
  values (new.following_id, new.follower_id, 'follow');
  return new;
end;
$$;

  with check (

create or replace function public.is_org_member(oid uuid, uid uuid)
returns boolean language sql stable security definer set search_path = public
as $$
  select (coalesce(uid = auth.uid(), false) or auth.uid() is null)
     and exists (select 1 from public.org_members where org_id = oid and user_id = uid);
$$;

create or replace function public.org_member_role(oid uuid, uid uuid)
returns text language sql stable security definer set search_path = public
as $$
  select role from public.org_members
   where org_id = oid and user_id = uid
     and (coalesce(uid = auth.uid(), false) or auth.uid() is null);
$$;

create or replace function public.can_view_org_channel(cid uuid, uid uuid)
returns boolean language sql stable security definer set search_path = public
as $$
  select case
    when not (coalesce(uid = auth.uid(), false) or auth.uid() is null) then false
    when c.org_id is null then false
    when not public.is_org_member(c.org_id, uid) then false
    when c.is_private = false then true
    when public.org_member_role(c.org_id, uid) in ('owner','admin') then true
    else exists (
      select 1 from public.org_channel_members ocm
       where ocm.channel_id = cid and ocm.user_id = uid
    )
  end
  from public.channels c
  where c.id = cid;
$$;

   - `post_comments`, `connections` and `post_reposts` still grant INSERT to `authenticated`, so the comment (30/300 s) and follow (60/600 s)
     route limits can be bypassed over REST. Follow notification spam is closed by B4. Comment notification spam is not.
     `repost` and `save` have no rate limit at all.
   - `GET /api/posts/[id]` (`src/app/api/posts/[id]/route.ts:88-99`) doesn't select `org_id`, and returns a hidden club's post text to any
     signed-in student who has its id. D closes only the media and uuid leak.
   - `record_post_view` counts views on drafts and hidden-club posts when the id is known.
   - Most `public` tables still grant TRUNCATE, REFERENCES and TRIGGER to `anon` and `authenticated`. PostgREST can't reach them, so this is hygiene only.
