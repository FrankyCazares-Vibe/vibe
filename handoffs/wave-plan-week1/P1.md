**Risks**
1. Deploy order. Applying the migration before the P1 code is live breaks every profile save, tag edit and pin (the HEAD routes write with the cookie client). The pre-check makes "P1 is serving" a hard gate; rollback is two GRANTs.
2. Service-role writes remove the grant as a second net under the two profile routes. `SELF_PROFILE_WRITE_COLUMNS` + `unexpectedSelfWriteKeys` put a closed list back in front of the write, and the test pins it; anyone adding a new writable profile field must add it to the list on purpose.

Text a student types into that empty card on an old bundle is dropped without an error. Nothing fails; the card disappears on the next load of the new page.
