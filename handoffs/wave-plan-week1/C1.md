   ```ts
   export const MOBILE_TAB_HREFS = ["/campus", "/network", "/otto", "/messages", "/profile"] as const;
   export type MobileTabHref = (typeof MOBILE_TAB_HREFS)[number];

   /** Routes outside the five tabs that belong under one of them on a phone. */
   export const MOBILE_TAB_SECTIONS: ReadonlyArray<readonly [base: string, tab: MobileTabHref]> =
     Object.freeze([
       ["/orgs", "/campus"], // a club page is reached from Campus → Orgs
       ["/plus", "/profile"], // your plan is account business, next to Settings
     ] as const);

   /** The tab that lights for this pathname, or null for none. */
   export function activeMobileTab(pathname: string | null | undefined): MobileTabHref | null;
   ```
   - `under(p, base) = p === base || p.startsWith(base + "/")`
   - `null`, `undefined` or `""` → `null`
   - Check the five tabs first, in `MOBILE_TAB_HREFS` order. This keeps today's rule exactly, including `/profile/<handle>` → `"/profile"`.
   - Then check `MOBILE_TAB_SECTIONS` in order.

**Risks**
1. Signed-out visitors get no bar. This is a decision for Franky: /profile/[handle] shows the bar to signed-out visitors, so the two public share pages now differ. To use the bar as a sign-in funnel, drop the `user ?` guard in both pages; each tab then bounces to login with `next` (`campus-access.ts:20`).
2. `:has()` needs iOS Safari 15.4+ or Chrome 105+. Older engines keep the bar over the org dialogs, so on short screens a footer can sit behind it: degraded, not broken. A future dialog that portals to `<body>` below z 9988 is outside `.vibe-tabbar-page` and won't hide the bar. Give such dialogs z ≥ 10000, as OrgInviteSheet has.
3. The `aria-current` change reaches every route with the bar, so subroutes announce "current". Nothing reads the attribute today (Fact 6). Re-grep before merge.
4. On phones, Next `<Link>` prefetches the five tab routes once they are in view. They are dynamic, so only the route shell is fetched, the same cost as every other route with the bar. On desktop the hidden nav never intersects the viewport, so nothing is prefetched.
5. Status-bar legibility in the standalone/Capacitor shell: `themeColor #FAF7F2` (`layout.tsx:31`) sits over the club's dark backdrop. Out of scope; flag it if E9 shows unreadable status-bar text.
6. From 721px to 899px the bar sits over the two-column org layout. Moving the org collapse to 899px is a separate design call.
7. `globals.css` and `MobileTabBar.tsx` are shared hot files. Rebase after any batch that edits them. The new CSS block goes directly after the `.vibe-org-content[data-tab="about"]` rules.
