A2. **Pure core `src/lib/email/send-log-core.ts`.** It has no `server-only` import and imports only `createHmac` and `createHash` from `node:crypto`. It uses erasable TypeScript only (no enums, no parameter properties) so that `node --experimental-strip-types` can load it. Exports:
   ```ts
   export const EMAIL_SEND_KINDS = ["school_verification", "password_reset"] as const;
   export type EmailSendKind = (typeof EMAIL_SEND_KINDS)[number];
   export const HASH_LABEL = "email-send-v1|";
   export type ProviderResult = {
     data?: { id?: unknown } | null;
     error?: { name?: unknown; message?: unknown; statusCode?: unknown } | null;
   };
   export type SendOutcome =
     | { ok: true; providerMessageId: string | null }
     | { ok: false; errorCode: string; errorMessage: string; httpStatus: number | null };
   export type EmailSendRow = {
     kind: EmailSendKind; user_id: string | null; recipient_domain: string;
     recipient_hash: string | null; provider_message_id: string | null; ok: boolean;
     error_code: string | null; error_message: string | null; http_status: number | null;
   };
   export function canonicalRecipient(address: string): string;
   export function recipientDomain(address: string): string;
   export function recipientHash(address: string, secret: string | null | undefined): string | null;
   export function recipientRateKey(address: string, secret: string | null | undefined): string;
   export function redactAddresses(text: string): string;
   export function outcomeFromProvider(result: ProviderResult | null | undefined): SendOutcome;
   export function outcomeFromException(err: unknown): SendOutcome;
   export function buildEmailSendRow(input: {
     kind: EmailSendKind; userId: string | null; to: string;
     secret: string | null | undefined; outcome: SendOutcome;
   }): EmailSendRow;
   export async function sendWithLog(opts: {
     kind: EmailSendKind; to: string; userId: string | null; secret: string | null | undefined;
     send: () => Promise<ProviderResult>;
     insert: (row: EmailSendRow) => Promise<unknown>;
     onLogError?: (message: string) => void;
     logTimeoutMs?: number; // default 2000
   }): Promise<SendOutcome>;
   ```
   Semantics. Each rule is exact, and the tests pin it:
   - `canonicalRecipient`: `trim()` then `toLowerCase()`. When the address contains `@`, trailing dots are stripped from the host after the LAST `@`. This matches `normalizeSchoolEmail` (`src/lib/auth/school-email-domains.ts:288-293`) for school addresses, and the reset route's `trim().toLowerCase()` (`src/app/api/auth/password-reset/route.ts:47-48`) for the rest.
   - `recipientDomain`: the canonical host after the last `@`, cut to 253 chars. When there is no `@` or the host is empty, it is `"unknown"`. It never contains `@`.
   - `recipientHash`: `createHmac("sha256", secret).update(HASH_LABEL + canonicalRecipient(address)).digest("hex")`, which is 64 lowercase hex. It returns `null` when `secret` is missing or shorter than 16 chars after trim, which is the same bar as `isSchoolVerifySecretConfigured` (`src/lib/auth/school-email-token.ts:20-23`). The HMAC key is `secret.trim()`, so callers may pass the raw env value. **Deliberate refinement of the brief:** the brief says "HMAC of the lowercased address". The `HASH_LABEL` prefix separates this use of `SCHOOL_EMAIL_VERIFY_SECRET` from its two existing uses: the token signature (`school-email-token.ts:59`) and the `vibe-school-code-v1|` code HMAC (`:114-116`). The label is harmless because the writer and the lookup script call this one function.
   - `recipientRateKey`: returns `recipientHash(...)` when it is non-null. Otherwise it returns `"u" + createHash("sha256").update(HASH_LABEL + canonical).digest("hex")`. It never contains `@`.
   - `redactAddresses`: first `text.replace(/[^\s@<>()"',;:]+@[^\s@<>()"',;:]+/g, "[address]")`, then every remaining `@` becomes `" at "`. The output never contains `@`. The DB CHECKs in A1 depend on that. Backticks are deliberately left out of the excluded set: Resend's 422 message wraps `email@example.com` in backticks, and the whole token, backticks included, becomes `[address]`.
   - `outcomeFromProvider`: when `error` is a non-null object, the result is `{ ok:false, errorCode: typeof name === "string" && name ? name : "unknown", errorMessage: typeof message === "string" ? message : "", httpStatus: Number.isInteger(statusCode) && 100 <= statusCode <= 599 ? statusCode : null }`. Otherwise it is `{ ok:true, providerMessageId: typeof data?.id === "string" && data.id ? data.id : null }`. It is total and never throws. Resend's shape is `{ data, error: { message, statusCode: number|null, name } }` (`node_modules/resend/dist/index.d.mts:122-135`). A network failure comes back as `name:"application_error", statusCode:null` (`index.mjs:1346-1356`).
   - `outcomeFromException(err)`: `{ ok:false, errorCode:"exception", errorMessage: err instanceof Error ? err.message : String(err), httpStatus:null }`. This covers `createResendClient()` / `getFrom()` throwing when env is missing.
   - `buildEmailSendRow`: `error_message = redactAddresses(outcome.errorMessage).slice(0, 500)`, or `null` when ok or when the message is empty. `error_code = redactAddresses(code).slice(0, 100)`. `provider_message_id = redactAddresses(id).slice(0, 200)`. `recipient_hash` is `recipientHash(to, secret)`. It never throws, including on `to = ""`, where the domain is `"unknown"`.
   - `sendWithLog`: (1) `try { outcome = outcomeFromProvider(await send()) } catch (e) { outcome = outcomeFromException(e) }`. (2) Inside its own `try/catch`, it builds the row and awaits `Promise.race([insert(row), timeout(logTimeoutMs)])`. The timeout resolves (it never rejects) and is cleared afterwards. On a reject or throw it calls `onLogError?.(msg)`, where `msg` is `redactAddresses(err.message)` or the fixed string `"timed out"`. (3) It returns `outcome`. **Logging never changes the outcome, never throws, and never waits longer than `logTimeoutMs`.**

create function public.email_sends_forget_recipient()
returns trigger
language plpgsql
set search_path = ''
as $$
begin
  if old.user_id is not null and new.user_id is null then
    new.recipient_hash := null;
  end if;
  return new;
end;
$$;

create trigger email_sends_forget_recipient
  before update of user_id on public.email_sends
  for each row execute function public.email_sends_forget_recipient();

revoke all on table public.email_sends from anon, authenticated;

**Risks**
- **Secret coupling.** The hash key is `SCHOOL_EMAIL_VERIFY_SECRET`. Rotating it orphans every earlier hash; it already invalidates open verification links and codes today. A lookup against production needs the **Vercel** value, and `.env.local` may hold a different one, so confirm it or use `vercel env pull` to a temp file first. The script tells the user this.
- **"Accepted" is not "delivered."** A row proves we tried and what Resend answered. Bounces, suppressions and Microsoft 365 quarantine (the likely Sebastian cause) need the Resend dashboard, keyed by `provider_message_id`, or a later Resend-webhook batch that updates rows by that id. Not in E1.
- **A failed send still spends one of the 3 hourly sends.** The limiter runs before the send (`school-email/request/route.ts:144-153`), and E1 does not change that. A student who hits a Resend outage three times is locked out for the hour. This is a Franky decision, not an E1 change.
- **Latency.** The school-email request awaits one extra PostgREST insert, typically about 50 ms and capped at 2 s by the race plus the abort signal. The reset path logs inside `after()`, so the response gets no slower.
- **GoTrue's cap was not verified against hosted production.** L-B1 checks the local CLI's GoTrue, which can be a different version from the hosted one. The client check stops nearly every over-cap password before GoTrue sees it, and `isPasswordTooLongError` covers the rest.
- **Ownership collisions.** `src/app/auth/school-email/page.tsx`, `signup/page.tsx` and `update-password/page.tsx` must not be owned by any other week-1 batch. The orchestrator should check the onboarding and campus batches. The migration stamp `20260922104000` must stay unique; P1 holds `20260922101100`.
- **The trigger relies on RI firing row triggers.** `ON DELETE SET NULL` runs as an UPDATE that fires `BEFORE UPDATE OF user_id` row triggers. L-A10 proves this locally. If it ever did not fire, rows of a deleted account would keep a keyed hash, which is pseudonymous and not reversible without the secret, and Privacy §5 would be only half true.
- **Adding a kind needs a migration.** A new send kind (org invites, digests) must extend `email_sends_kind_check` and `EMAIL_SEND_KINDS` together, or its insert fails. The failure is silent, by design.
- **`profile-patch` counts before the Terms gate**, the same as `handle` and `publish-post`. A user stuck in a `terms_required` loop spends budget. That is harmless at 30 per 10 minutes.
