## §1 — Root cause (measured on prod, Sept 13–14 cohort)

~9 real people made 10 accounts in 44 minutes, all iPhones, 5 inside Snapchat's in-app browser. **Every one of the 9 who tapped "Confirm my account" landed on "invalid or expired… or sign up again" while their account was already confirmed.**

| Cause | Reach |
|---|---|
| `/auth/callback` exchanged the PKCE code twice in the signup browser (auth-js auto-detect + the page's own call) — second one fails | 3 same-browser taps |
| PKCE binds the link to the signup browser — Gmail/Outlook in-app browser has no verifier | 5 |
| Microsoft Defender Safe Links GET-prefetched `{{ .ConfirmationURL }}` and burned the token | 1 (the only iu.edu signup) |
| One error screen for every outcome; "sign up again" sends nothing for a confirmed address but still says "check this inbox" | all 9; 2 accounts looped (9 repeat signups) |
| A second signUp from the same browser overwrites the PKCE verifier even when it 429s | ~3 plausible |

Refuted: IU email step (B) session binding/domain rejects, host mismatch, deliverability (confirm latency 13–100s; SPF/DKIM/DMARC aligned, `p=none`).
