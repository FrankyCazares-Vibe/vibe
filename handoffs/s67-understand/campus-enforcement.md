## Summary

- "IU sees only IU campuses / Purdue only Purdue" is ONE pure rule, `allowedCampusIdsFor(system)` (`src/lib/iu/campus-scope.ts:197-199`), applied by `resolveScopeV2` (`:209-232`, the `!allowed.includes(row.id)` at `:222`) and tightened by `resolveCampusRequest` (`src/lib/iu/campus-request.ts:96-107`). Nine API routes call one of the two. The DB has a matching trigger on `users` but NO RLS policy filters by system (checked below).
- A forbidden `?campus=` returns HTTP 403 `{ok:false, code:"campus_not_in_system", error:"That campus isn't part of your university."}`, an unknown id 400 `unknown_campus`, both from `campusScopeError` (`src/lib/iu/community-scope.ts:442-456`). Feed, events, orgs discover, campus-map, map zone and campus stats all use it. Search and trending never read `?campus=` (home lane only).
- Cross-campus READING is already the code's own stance: every header says "NOT A PRIVACY BOUNDARY ... RLS lets any signed-in user read these rows" (`campus-scope.ts:16-19,142-144`, `campus-request.ts:24-27`, `community-scope.ts:21-24`). For E the read side is: delete one `includes` check, widen one picker.
- Follows and DMs already work across campuses and systems (verified below: no `campus_id`/`school_system` read in those routes).
- RSVP, org join, org channels/chat and post create have NO campus check today (verified below). E's "no RSVP / no club chat away from home" is an ADD on 3-4 mutation routes, not a relax.
- Home-campus lock: `users.campus_set_at` exists and is written by `src/lib/profile/profile-campus-write.ts`; nothing reads it as a cooldown. The 45-day lock is one new predicate in the single campus writer.
- Picker/switcher (`/api/campuses` -> `campusOptionsForSystem`; `CampusSwitch.tsx`) show only the viewer's system's campuses; E needs all 11 grouped by system, with Indianapolis and Fort Wayne listed once as shared.

## How it works today

### (1) Where "IU sees only IU campuses / Purdue only Purdue" is enforced

Server, one rule, nine callers:
- `allowedCampusIdsFor(system)` `src/lib/iu/campus-scope.ts:197-199` = `campusesForSystem(system)` ids (`campuses.ts:276-279`, filters `CAMPUSES` on `c.systems.includes(s)`); a null system returns EVERY campus (legacy stragglers).
- `resolveScopeV2(raw, viewer)` `campus-scope.ts:209-232`: `?campus=<id>` -> `campusRowById` (`:220`); unknown -> `{kind:"forbidden", reason:"unknown_campus"}` (`:221`); **`!allowed.includes(row.id)` -> `{kind:"forbidden", reason:"campus_not_in_system"}` (`:222`)** -- this one line is the cross-system read block. `?campus=all` -> `{kind:"system", campusIds: allowed}` (`:218`) = own university only. Absent -> home campus when in the allowed set (`:228-229`) else `{kind:"none", campusIds: allowed}` (`:231`).
- `resolveCampusRequest` `src/lib/iu/campus-request.ts:96-107` wraps it and adds: named campus + viewer with no `school_system` -> forbidden (`:103-104`). Unverified accounts have no system (`campuses.ts:155-160`), so this is the "verified only" clamp for browsing.
- Callers with `?campus=`: feed `src/app/api/feed/route.ts:278` (calls `resolveScopeV2` directly, no no-system clamp), events `events/route.ts:160`, orgs discover `orgs/route.ts:216`, campus-map `campus-map/route.ts:125`, map zone `campus-map/zone/route.ts:98`, campus stats `stats/campus/route.ts:81`. Callers that pass `null` (home lane only, never forbidden): search `search/route.ts:144`, trending `trending/hashtags/route.ts:78`.

## Risks

- R1. The "system limits browsing" rule is documented as settled in three headers (`campus-scope.ts:135-141`, `campus-request.ts:82-95` "Franky's Q2", `community-scope.ts:16-24`) and in `handoffs/2026-09-15-indy-campus-onboarding-plan.md` §2.4; E reverses it. - R2. Cross-system browsing puts Purdue-only clubs (`orgs.audience = 'purdue'`) in front of IU viewers. `orgJoinState` already answers `audience_blocked` (403 `audience_mismatch`, `join/route.ts:154-162`), so nothing leaks, but the org list UI must render that state without a broken Join button.
- R3. A visited campus's map lists that campus's students by major (`campus-map/route.ts:136-140`, `users.campus_id in (...)`) and the zone route lists names. RLS already allows the read; the exposure is the same as today's own-campus map, now for every campus. Confirm this is wanted for closed campuses with a handful of signups (a two-person "Computer Science" zone identifies them).
- R4. Every campus but Indianapolis is `isOpen:false` with near-zero content.
