## Points for the integration pass (nothing here was improvised)

1. Section 8 says `name` and `is_private` are refused on a board, lounge or officers room. The desktop settings screen sends `name`, `topic`, `is_private` (and `pinned`) on EVERY save (campus-home.tsx:2069-2076 and :3350-3358), so a literal reading would make the topic of a core room impossible to edit there, against "topic, position, pinned allowed". Built: a `name` or `is_private` equal to what the room has is not a change and is not refused (and is not written); any real change is 409 `room_locked` and nothing in that request is written.
2. The 403 "Admin only", the 404s and the 401 of these routes have no `code` (they are the guard's answers from before wave 1; the contract names no code for them).
3. The 201 of POST …/channels and the 200 of PATCH carry today's keys, without `kind`. A screen that puts the answer straight into its list holds a row without `kind` until it reloads the list.
4. Names are unique per club by the routes' own check, which also counts event rooms (their name is the event's title). An event titled like a room name (one lower-case word, for example "formal") makes "Channel name already exists" for a room of that name, and the old list does not show why.
5. `…/channels/[channelId]/members` (the by-name list) and `subscribe-public` are unchanged: no bullet of section 8 names them. The by-name list can still be written for any room; it only ever opens a private `room` or the Officers room (`can_view_org_channel` ignores it for an event room).
