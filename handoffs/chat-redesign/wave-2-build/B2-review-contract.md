### B2-CONTRACT-2 — LOW — `buildChatMessages` takes a caller's block set even when `room === null`
- where: `src/lib/chat/message-read.ts` (`buildChatMessages`, the line `let blocked: ReadonlySet<string> = ctx.blocked ?? NO_BLOCKS;`).
- what: 9.1 pins "when `room === null`, `blocked` is the empty set and no read is made". The read is skipped correctly, but a set a caller passes is kept, and the quote rule below (`quoteShown = blocksRead && (preview === null || !blocked.has(preview.user_id))`) would then null a quote of a blocked member inside a group chat — 8.5 says a group with a blocked member "stays visible with all its messages". No caller does this today (the thread GET passes `new Set<string>()` for a dm or a group, `messages/route.ts`), so no answer changes; the rule is one line short of the contract's.
- fix: `let blocked: ReadonlySet<string> = room === null ? NO_BLOCKS : (ctx.blocked ?? NO_BLOCKS);` and one line in `message-read.test.ts`'s dm test passing `blocked: new Set([OTHER])` and asserting the quote stays.

### B2-CONTRACT-3 — LOW — `hydrateCards` is skipped when the block set could not be read; 9.1 lists it unconditionally

### B2-CONTRACT-4 — LOW — the viewer's own removed card is hydrated (5.2 says removed rows are filtered first)
- where: `src/lib/chat/message-read.ts` (`buildChatMessages`, `shown = rows.filter((row) => !row.removed_at || row.user_id === viewerId)` → `cardRows`).
- what: 5.2 says "A removed message is not given to it (`buildChatMessages` filters removed rows first, `message-read.ts:533`)". Judged as holding the contract's cited line rather than its sentence.
- fix: none required; if the sentence is what is meant, `cardRows` gains `&& !row.removed_at` and a test that a removed own poll answers `card: null`.
