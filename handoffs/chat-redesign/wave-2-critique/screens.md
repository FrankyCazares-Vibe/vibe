# Critique of `wave-2-contracts-draft1.md` — lens "screens" (S70, 2026-09-30, CLOUD session)

Read-only review of the phone screens the draft pins (sections 1.2, 1.4, 2, 11, 14, and the screen rows of 8.3, 12, 13) against the 13 mockups (`handoffs/chat-redesign/boards/W0_*.dc.html`, read as text with `grep` / `sed`), the mockups map (`wave-2-asis/mockups-map.md`, MK), the MessagesMobile map (MM), `src/lib/chat/types.ts` (TY), `wave-1-contracts.md` sections 6.0, 7, 12, 14–16, `wave-0-decisions.md`, `wave-plan.md` section 1, `plan-critique.md`, and the code the draft cites (`MessagesMobile.tsx`, `CampusMobile.tsx`, `MobileShell.tsx`, `MobileTabBar.tsx`, `globals.css`, `LoadFailed.tsx`, `ReportSheet.tsx`, `room-state.ts`, `layout.tsx`, the calendar / events / rsvp routes). Nothing was run: no browser, no database. Every code fact is `path:line` from `sed -n` / `grep -n`; every mockup fact is `W0_<Name>:<line>`. The routes, database, split, privacy and schedule lenses are left alone except where a screen adds evidence.

## Verdict

**Buildable after the changes below.** The copy strings, `aria-label`s, placeholders and the empty-state copy match the mockups word for word (checked with `grep -o 'aria-label="…"'` over all 13 files); every mockup element without a payload field has a v1 substitute written down; the "Your week" block is capped so the first chat row lands at the mockup's y 249; Requests stay; the Board folds and stays quiet; the "+" tray is club-only; the Discord tells are absent. What does not hold: (1) the tab bar does NOT hide "for free" under a `Drawer.Root` — it is `position: fixed; z-index: 9988` and paints over the drawer's z 1100 composer unless the new view adds `body.vibe-composer-open` itself, and the counter-less class breaks again the moment the event chat is a second layer; (2) the event chat is drawn as its own screen (W0_Room: `Back to Salsa Club`, no chips, no Up next) while 11.3 nests it under the club's chips — W2-S2 cannot build both; (3) the `Soon` mark and the bloom are pinned to `state === "soon"`, which is every future event, while the mockup gives them to tonight's event only; (4) every title, wordmark and CTA is pinned at weight 800 and the app loads neither Fraunces nor DM Sans at 800; (5) the Light theme's muted token fails 4.5:1 for the twelve-pixel labels the draft calls "muted"; (6) the history rule leaves a stale `?channel=` after Back; (7) `ThreadRow` "as today" puts `3h` next to `8:41 PM` in one list and W2-S1 may not edit it.

Counts: **1 HIGH, 7 MEDIUM, 14 LOW.**

**The top changes**

1. **Hide the tab bar on purpose** (H1): one owner of `body.vibe-composer-open` for the whole club stack (a counted hook in a new file), set by `ClubSpace` on mount; the event chat layer and the sheets never touch it.
2. **Make the event chat its own layer** (M1): W0_Room over the club space, pushed by an event chip / Up next card / week card / `Open event chat`, Back → the space; 11.3's "the room (… or the event chat)" goes.
3. **Pin "Soon" as tonight, not as `state === "soon"`** (M2): the ring, the live chrome and the bloom for `live`, or `soon` starting within 24 h; every other future card is quiet.
4. **Load the weights the mockups use, or pin the ones the app has** (M3): `layout.tsx:96` adds `0,800` for Fraunces and `800` for DM Sans (W2-S1's first commit), and the SOFT axis is dropped from the pin.
5. **Fix the Light muted token** (M4): `palette(false).muted = var(--ink-sub)` (#5A564F, 6.8:1), never `--ink-muted` (#8A8580, 3.5:1) for a 10.5–12.5px label; the Light live/soon card marks use `#B5381A`.

Severity: **HIGH** = built literally it breaks something, leaks something, or a batch cannot finish. **MEDIUM** = real rework, a missed file, or a payload a screen cannot use. **LOW** = wording to pin.

**SCREENS-H1. The tab bar does not hide "for free": it is fixed at z-index 9988 over the drawer's 1100, and the counter-less body class breaks again as soon as the club stack has two layers.**
- Evidence:
  - Draft 11.3: `ClubSpace` is "a `Drawer.Root direction="right"` like `ConversationView` … so the slide and the `vibe-composer-open` body class come free." Draft 11.0: "the tab bar … is hidden while a club space or a conversation is open through the existing `body.vibe-composer-open` class".

A new `ClubSpace` that only mounts a `Drawer.Root` sets nothing.
  - Without the class the bar paints ON TOP of the drawer: `.vibe-mobile-tabbar { position: fixed; bottom: 0; z-index: 9988 }` (`src/app/globals.css:2857-2862`) vs `Drawer.Content` `zIndex: 1100` (`MessagesMobile.tsx:1575-1592`). - Change (11.0, 11.3, 11.6, 11.7, 13.2):
  - New file **`src/lib/chat/use-hide-tabbar.ts`** (W2-S1's first commit): `useHideTabBar()` keeps a module-level count; the first mount adds `vibe-composer-open`, the last unmount removes it. `ClubSpace`, the event chat layer, `CardSheet` and the RSVP sheet all call it; nothing else in the club stack touches `document.body.classList`.
  - 11.3: replace "come free" with "the slide comes from `Drawer.Root`; the tab bar is hidden by `useHideTabBar()` (counted), called by `ClubSpace` on mount."
  - 11.10: "The tab bar: hidden while a space, an event chat or a conversation is open (`useHideTabBar`); the old boolean mounters are untouched." Keep the MM:9 note for the OLD screens only.
  - 13.3 (the design review by reading): "the reviewer checks that every full-screen layer under `messages/club/*` and `messages/compose/*` calls `useHideTabBar` and none writes the class directly."
