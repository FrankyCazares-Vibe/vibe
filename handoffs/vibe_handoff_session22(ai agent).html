The big strategic shift this session

Vibe is now positioned as "the network where your AI agent lives." Otto became the flagship feature in v3.3 and the defensibility argument in v3.4. Other social networks can copy the UI; they cannot easily copy a per-user trained AI agent that manages cross-platform posting and shows users who's looking at them. This reframing should drive every product, marketing, and pitch decision going forward.

Locked decisions
Don't relitigate these
Product decisions
  • Feed layout — Layout B. Posts as editorial center column, Vibes thumbnails as right sidebar strip.
  • Comment depth — One level of nested replies. No Reddit-style infinite threading.
  • DM model — Three-column thread list. Non-connected users land in a request queue with Accept / Decline before they enter the inbox.
  • Connection vs Follow — Hybrid. Follow is one-way for content. Connect is mutual and requires acceptance. Four-state machine across the app.
  • Profile layout — Horizontal top nav (different from the rest of the app). Intentional, do not "fix" this.
Otto decisions
  • Otto's character — Jarvis lane (sleek, dry, opinionated). NOT Wall-E lane (cute helper bot). Voice is short, slightly dry, opinionated, lowercase-leaning, italic Fraunces in the UI.
  • Visual language — Coral core + orbiting nodes + breathing rings. Four states: idle, thinking, briefing (sound bars), alert. Coral = action, deep purple = intelligence.
  • Agent tab structure — 5 sub-tabs: Today, Metrics, Insights, Customize, Platforms.
  • API reality — LinkedIn analytics scraping is not feasible. Pivoted to Vibe Recruiter Intel (first-party data on Vibe profile views) as the killer free-tier feature.
  • Onboarding — 6 steps in ~3 minutes. Ends with Otto generating a real draft from voice samples.
  • Default Otto leash — "Ask first." Users graduate to Full auto over weeks.
Design decisions
  • No-emoji policy in chrome — buttons, nav, badges, callouts all use custom SVG icons. Emoji are permitted only inside user-generated content (post bodies, comments, message bubbles).
  • Typography — Fraunces (serif, display) + DM Sans (geometric sans). Otto always speaks in italic Fraunces.
  • Cursor — orange dot (instant, zero lerp) + trailing ring (lerp 0.28). cursor:none on every element.
  • Mobile — separate codebase eventually, not media queries on desktop files. Out of scope right now.
  • Backend — out of scope until front-end is fully built. Mock data for now.
Bug traps
Things that silently break
JavaScript
  • Apostrophes in single-quoted JS strings crash silently. Always validate with node --check after editing data. Use double-quoted strings for content with apostrophes. Cost an entire debugging session in v3.3.
  • Cursor init must use center coords. let mx=window.innerWidth/2,my=window.innerHeight/2,rx=mx,ry=my — never (0,0). Cursor IIFE must expose cur and ring to window so external hover handlers work.
  • Cursor must use event delegation for hover state. Static querySelectorAll patterns freeze on dynamic content.
CSS
  • backdrop-filter on modal backdrops creates GPU compositing layers that swallow fixed-position children. Do not use on .cal-modal-backdrop etc.
  • Inline display:none cannot be overridden by CSS class. Use CSS-only visibility control.
  • cursor:none appears 25-80x per file. Stripping it brings back the Mac cursor. Keep it everywhere.
  • DevTools open disables cursor:none by browser design. Not a bug.
Workflow
  • Browser cache is aggressive. When something looks unchanged, hard refresh first (Cmd+Shift+R). If still no change → DevTools → Application → Storage → Clear site data. Or test in Incognito.
  • All hrefs use absolute paths starting with /html/ (e.g., /html/feed.html).
  • Next.js routing — folder names must be lowercase. Page files must be page.tsx lowercase.
The path forward
What comes next
Session 23 — pick this up first
Empty states across all 7 pages
Every page is currently seeded with mock data. A real new user would see populated content that isn't theirs, which is broken UX. Each page needs an empty state with Otto as the next-action invitation.
Pages that need empty states:
  • Feed — "no posts yet · post your first thing"
  • Profile — "your profile is empty · let's fill it in"
  • Network — "no connections yet · find people"
  • Campus — "verify your .edu to unlock"
  • Opportunities — "no matches yet · finish your profile to see opportunities"
  • Messages — "no messages yet · DMs unlock when you connect with someone"
  • Agent — "let's set otto up · 3 minutes to your first draft"
