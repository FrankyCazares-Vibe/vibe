## Club posts, club deletion, clients
- Club media all lives in R2 `orgs/<org_id>/<banner|logo|posts>/<uuid>.<ext>` (`orgs/[slug]/upload-url/route.ts:167-172`). R2 is private (served only through signed URLs from proxy routes that re-check the org/post), so leftover R2 files are a retention/cost issue, not public exposure — unlike the public `profiles` bucket.
- A club post may name ANY key under `orgs/<org_id>/` (isAllowedMediaUrl `org-asset-url.ts:108` + post_media_ref_ok), including the club's own logo/banner key. So a club-post purge must (a) only delete `orgs/<org_id>/posts/` keys and (b) skip keys the org's logo_url/banner_url or any other post names — else an officer (or ex-officer) deleting a planted post erases the club's logo.
- posts_org_id_fkey SET NULL evidence: org_content_visible gates club posts on hidden clubs; after SET NULL, `org_id IS NULL` skips that clause in posts_select_authenticated, so a HIDDEN club's member-only posts become readable by every signed-in student on the campus the moment the owner deletes the club. Also the post's R2 media 404s (postMediaKeyKind needs org_id) and the author can now freely edit words published as the club (posts_update_own club clause no longer applies). => CASCADE.
- CASCADE caveat: it would hard-delete a moderator-REMOVED club post (evidence) — the same bypass as an author deleting a removed post, via "delete the whole club". Route fix: before `orgs.delete()`, detach removed club posts (`update posts set org_id = null where org_id = X and removed_at is not null`, service role). They stay removed (invisible to all but author + admins), keep campus_id, and B2's new policies stop the author editing or deleting them.
- FKs into posts: bookmarks/post_likes/post_comments/post_reposts/post_views/notifications CASCADE, users.pinned_post_id + messages.attachment_id SET NULL. Reports have NO FK to posts (target id is loose) — report snapshots survive a delete.
- Clients that DELETE a post: `src/components/mobile/PostViewerMobile.tsx:208-226` (vibeRequest, failure copy "Couldn't delete this post."; a 409 with a human-sentence `error` is shown as-is via failure-copy.ts:211) and `public/html/_postViewer.js:1494-1522` (shows `j.error` raw). Both show Delete (and Edit) whenever `is_owner`, including on the author's own REMOVED post — after B2 that tap gets a refusal. Hiding Delete/Edit on a removed post and adding an officer Delete are UI edits in files B2 does not own.
- Tag filter on PATCH: tags are derived from content (`extractPostTags` edit.ts:39) and content already goes through checkText (:608). checkText's `\bterm\b` treats `_` as a word char, so `#slur_club` passes BOTH checks.
